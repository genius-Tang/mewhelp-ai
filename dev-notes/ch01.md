## 2026-09-22 · Brainstorm 定稿

### 用户关键原话

- “我要用 Superpowers 模式做一个电商智能客服系统，第一步先跑通纯对话。”
- “对话接口：支持多轮对话、SSE 流式输出、逐 token 推送。”
- “Prompt 管理：用 PromptTemplate 模板化，System Prompt 写清客服角色设定和行为约束。”
- “结构化输出小功能……用 with_structured_output 实现。”
- “多轮上下文先做最简版：历史消息裁剪加 token 预算控制。”
- “全程走 Superpowers 流程……涉及具体库、框架、API 的用法，一律先用 Context7 MCP 查最新官方文档和接口定义再动手。”

### 关键产出与评审结论

- 选定轻量分层架构：`api/` 负责 HTTP/SSE，`core/` 负责配置、模型、Prompt 与消息裁剪，`services/` 负责对话流和结构化提取。
- 多轮对话采用无状态方案：客户端每次提交完整 `messages`，服务端负责裁剪；默认预算 `HISTORY_MAX_TOKENS=4000`。
- 接口定为 `POST /chat/stream` 与 `POST /extract/after-sales`。
- SSE 使用 JSON 事件：`token`、`done`、`error`；“逐 token”落地为上游每产生一个非空文本增量就立即转发，不人为重新分词。
- 结构化字段定为 `order_id`、`request_type`、`expected_solution`；无法识别时使用 `null` 或 `其他`，不猜测。
- OpenAI 兼容模型统一通过 `ChatOpenAI` 接入；本章不实现 Claude 原生适配。
- Context7 已核对 FastAPI `StreamingResponse`、LangChain `ChatPromptTemplate`、`trim_messages`、`count_tokens_approximately` 和 `with_structured_output` 的当前接口。
- 正式设计：`docs/superpowers/specs/2026-09-22-ch01-pure-chat-design.md`。

### 用户拒绝或纠偏

- 用户明确原本不准备使用 Claude，接受本章仅支持 OpenAI 兼容端点，不实现 Anthropic 原生协议。
- 用户接受模型流式 chunk 不保证严格等于单个 tokenizer token，改以“非空增量立即转发”作为验收定义。
- 因不同上游对结构化输出模式支持不一致，用户接受增加 `CHAT_STRUCTURED_OUTPUT_METHOD`，默认 `function_calling`，可切换 `json_mode` 或 `json_schema`。
