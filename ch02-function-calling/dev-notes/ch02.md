### 仓库探索

- `ch01-pure-chat/` 是现有可运行的 SSE 客服章节；本章采用同级独立快照
  `ch02-function-calling/`，不直接修改第一章。
- `MewHelp_AI/python/` 中存在后续教程参考实现，仅做只读对照；本章不修改该目录，也不直接
  复制其中的后续实现。

### 方案取舍

- 采用手写一次工具编排器：第一次 `bind_tools().ainvoke()` 只做工具决策，工具执行后由未绑定
  工具的原模型 `astream()` 流式收敛。
- 未采用 LangChain Agent/AgentExecutor，因为其循环语义会增加越过“只调用一次”范围的风险。
- 未把编排逻辑直接堆进 FastAPI 路由，以保持 API、领域编排、工具执行和数据库职责独立。
- 无工具分支也执行一次未绑定工具的流式收敛，确保所有最终回答都按 SSE 增量输出。
- 每轮最多接受一个工具申请；上游返回多个工具时拒绝执行，不擅自挑选。

### Context7 核对

- LangChain：确认当前 `@tool(args_schema=...)`、`bind_tools()`、`AIMessage.tool_calls` 和
  ToolMessage `tool_call_id` 回灌流程。
- SQLAlchemy 2.x：确认 Declarative 映射、`mapped_column()`、session/事务上下文和字面
  `LIKE` 查询接口。
- FastAPI：确认异步生成器可交给 `StreamingResponse`，并需保留取消传播所需的 await 点。

### 设计产出

- 书面设计：`docs/superpowers/specs/2026-09-23-ch02-function-calling-design.md`。
- 固定边界：FastAPI + SQLAlchemy async + Docker MySQL + LangChain `@tool`；不做 Agent Loop、
  RAG 或真实订单/物流接口。
- 第一项实施任务必须先验证当前真实模型的 Function Calling 能力；失败时停止并请用户决定，
  不自行更换模型或技术路线。
- 本阶段只创建设计文档与过程记录，尚未创建产品代码、安装依赖或运行实现测试。

## 2026-09-29 · 最终审查补修：锁连接池隔离

- 复审发现上一修复在整个流式轮次持有业务连接池里的 MySQL 连接，多个不同会话可占满连接池，使同一轮的消息写入超时。先用 `pool_size=2`、`max_overflow=0` 的真实 MySQL 回归测试复现：两个不同会话各占一个锁连接后，首条 `append_message` 稳定报 QueuePool 超时。
- 锁连接现从独立 `NullPool` 引擎取得，保留 MySQL 连接级 advisory lock 的跨 worker 语义与即时冲突拒绝；业务读写仍用原业务池。Repository 在应用 lifespan 退出和评估脚本退出时关闭专用引擎，且初始化失败路径仍会释放业务引擎。非 MySQL 回退及四表 DDL 均未改变。修后相关 18 测试通过，完整 pytest `102 passed in 3.93s`；compileall 与 `git diff --check` 均退出 0。本轮未重跑联网评估或操作 Docker。
