### 方案取舍

- 采用手写一次工具编排器：第一次 `bind_tools().ainvoke()` 只做工具决策，工具执行后由未绑定
  工具的原模型 `astream()` 流式收敛。
- 未采用 LangChain Agent/AgentExecutor，因为其循环语义会增加越过“只调用一次”范围的风险。
- 未把编排逻辑直接堆进 FastAPI 路由，以保持 API、领域编排、工具执行和数据库职责独立。
- 无工具分支也执行一次未绑定工具的流式收敛，确保所有最终回答都按 SSE 增量输出。
- 每轮最多接受一个工具申请；上游返回多个工具时拒绝执行，不擅自挑选。

### Context7 核对

- LangChain：确认当前 `@tool(args_schema=...)`、`bind_tools()`、`AIMessage.tool_calls` 和
  ToolMessage `tool_call_id` 回灌流程。
- SQLAlchemy 2.x：确认 Declarative 映射、`mapped_column()`、session/事务上下文和字面
  `LIKE` 查询接口。
- FastAPI：确认异步生成器可交给 `StreamingResponse`，并需保留取消传播所需的 await 点。
